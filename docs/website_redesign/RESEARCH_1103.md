## 3. Animations and components: code read

| Source | What was read | Decision for this build |
|---|---|---|
| **Motion** (motion.dev, React docs on scroll) | `whileInView` + `viewport: { once }` on a pooled IntersectionObserver; `useScroll({ target, offset })` + `useTransform` for scroll-linked values, native `ScrollTimeline` where the browser has it; `useSpring` to smooth | **Used.** The repo already ships `framer-motion` 11 with `LazyMotion` + `m`; the same API. No new dependency. |
| **GSAP ScrollTrigger** (gsap.com docs + pricing) | `scrub`, `pin`, `start/end`, `toggleActions`, `batch`; GSAP is free since Webflow's sponsorship; do not animate pinned elements, avoid `will-change` on ancestors | **Not added.** Pinning is done with CSS `position: sticky` + Motion's scroll progress; one fewer 70 kB library on the mobile budget. |
| **Lenis** (github darkroomengineering/lenis) | wraps native scroll, keeps `position: sticky`, `respectReducedMotion` on by default, 60 fps cap on Safari, no scroll-snap | **Not added.** Smooth scroll fights the reduced-motion rule and iOS momentum; the owner's §8 asks for the visitor to be able to read and decide. |
| **Magic UI · Animated Beam** (`apps/www/registry/magicui/animated-beam.tsx`) | an SVG path measured from two refs with a ResizeObserver, a `linearGradient` whose `x1/x2` animate from 10 %→110 % | **Already in the repo** as `components/ui/animated-beam.tsx` (adapted, MIT). Used in the flow ribbon (Consulta → Nuova → Ficha → Tu equipo). |
| **Magic UI · Number Ticker** (`number-ticker.tsx`) | `useInView(once)`, `useMotionValue` + `useSpring(damping 60, stiffness 100)`, writes `textContent` with `Intl.NumberFormat` | **Rewritten** as `components/ui/count-up.tsx` for the reporting figures (locale-aware format, reduced motion = final number at once). |
| **Magic UI · Animated List** | items arriving in order | **Already in the repo** as `components/ui/animated-list.tsx` (adapted). |
| **Aceternity · Sticky Scroll Reveal** (`/r/sticky-scroll-reveal.json`, docs) | left text column scrolls, right panel sticks; `useScroll` progress chooses the active card by the nearest breakpoint | **Pattern used** for the core-functions section (`components/home/functions.tsx`): left list of functions, right sticky product surface that swaps; on the phone a linear stack (owner §8: no scroll trap on mobile). |
| **21st.dev** | a catalogue of hero, pricing and testimonial blocks installed through the shadcn CLI | Looked at for the pricing table pattern (icon + status cell per row); nothing installed, the plans table is our own markup. |

**Performance plan:** one film in the hero (mp4, `preload="metadata"`, poster first; no film on `saveData`, slow effective
connection or reduced motion); the 3D clean take loads only on play; every scroll animation is a transform/opacity on the
compositor; `content-visibility` not used on animation ancestors (GSAP's own warning applies to sticky as well); the
page ships no new JavaScript library.

## 4. The critical check of the order (five lines, as asked; implemented without waiting)

1. **The "7-second film" of C01 is not in `handoff_2026-10-30`.** C01 shows `living-camera-ride.mp4` (the 3D lane's living-room
   study, 1280 × 720, 8 s, handoff 2026-10-02). The clean take of 30.10. is the whole house from above (25 s, 1080p). The hero
   uses the living-room ride (what the owner pointed at); the clean take replaces `house-turn-es.mp4` on the 3D stage. Both
   are named with checksums in the return.
2. **A 15 MB clean take must not autoplay.** It plays on click with its own poster (the 4K "02 Modelo" frame, resized); the
   stage itself is plan → model → empty/furnished and does not wait for the film.
3. **"Recommended plan" and "no invented 'most popular' claim" (report §2 G) are reconciled** by marking Essential
   "Recomendado para empezar": it is the one plan whose rows are included today. Nothing is called popular.
4. **The demo cannot show a WhatsApp "delivered" tick** without claiming delivery (Copy 1102 v2 §1.2: a sent text is not a
   received one). The reply bubble shows a time on both sides and one grey tick (sent), never two blue ones.
5. **Lighthouse mobile ≥ 85 and a background film on the phone are in tension.** On viewports under 768 px the hero shows the
   poster and plays the film only after the first paint and only on a fast connection; the measurement is reported as
   measured, not promised.
