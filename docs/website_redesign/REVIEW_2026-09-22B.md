## 3. R2 — the registration path, and why the owner's test failed

Two proofs were asked for. **Neither can be closed by the reviewer today**, and the cause of the owner's
failure is not the confirmation mail but the website's own call:

**WR-35 (P0 for the registration path, Website).** `app/api/bff/signup/route.ts:43` calls `signUp(email, password, meta, null)`
— the fourth argument is the redirect target, and it is always `null`. `lib/contracts/supabase.ts:89` therefore
sends no `redirect_to`, so the identity server builds the confirmation link from its own `site_url`, currently
`http://localhost:3000`. Consequence: the confirmation link can only work on a machine that is running the site
locally at that moment. That is exactly what the owner saw (account confirmed at 15:11:10Z, link not reachable,
no agency created). A deployed preview or staging domain cannot complete the path even after the allow-list is
extended, until the website passes a `redirect_to` of its own origin.
Closing: `redirect_to` per build origin (Website) **and** `STG_AUTH_REDIRECTS` (API). Both are needed.

**A) Confirmed owner account → login → resume.** The contract exists: `session` answers `next: register | onboarding`
and the register route creates agency, first admin and the 14-day trial in one backend call, answering
`already_registered` on a repeat (`app/api/bff/register/route.ts`). The reviewer could verify the routing only for an
identity that already has an agency (`next: onboarding`, RV-25). The owner's identity has no agency, and the reviewer
has neither its password nor a second confirmed identity without an agency. **Not run**, not refuted.

**B) New identity with a real mailbox.** Still blocked: public sign-up with `test.nuovasolution.com` is refused by the
identity server (RV-24), and the reviewer has no allow-listed address. Needed from API: one reviewer address on the
allow-list or a deliverable test domain, plus the redirect allow-list. Double click, parallel submit, expired link,
same-device and other-device recovery are prepared in the probe and run in one pass once an address exists.

The rate limit the owner hit is real and is reported to the user, not swallowed: 429 `rate_limited` (RV-23).
