## 4. Das eine System (Handy + Desktop)

- **Farbe:** Owner-Wahl **D**: Akzent `#1f4e8c` (Mittelmeerblau, 8,3 : 1 auf Weiß), Tinte `#173a68`, Wash `#e9eff8`; Bronze nur als Hauch im Hero-Häkchen, nie auf Knöpfen. Knöpfe: Schwarz (Haupt) / Weiß mit Rahmen (Neben). Beige nur unter Bericht und Planes. Grün nur am WhatsApp-Zeichen. Diagramme in Tönungen von D. Paleta-Schalter A/B/C/E werden entfernt.
- **Muster-Satz (mehr nicht):** Hero mit Bewegung · Live-Demo mit Auto-Lauf · Scroll-Erzählung (sticky) · gestapelte Karten · Erkenntnis-Karten · Vergleich (max. 4 Zeilen) · aufgehende Schritt-Karten (Tu camino, Cómo empezar).
- **Bewegung:** `app/motion.css` bleibt die eine Quelle (eine Kurve, 120/200/360/560 ms). Einblenden mit Versatz, hochzählende Zahlen, sticky Abschnitte, Mikro-Animation im Produkt (Nachricht tippt, Foto/PDF fliegt ein, Ficha füllt sich, Badge „Alta“), Hover-Anheben/Druck, Parallax nur im Hero. Nur `transform`/`opacity`; `prefers-reduced-motion` = Endzustand sofort; ohne JS alles sichtbar.
- **Typografie:** Inter; Fraunces nur als Variante für Überschriften (bleibt schaltbar bis zur Owner-Wahl). Je Abschnitt 1 Überschrift + 1 Satz sichtbar.
- **Text:** „Datos de ejemplo“ einmal je Abschnitt als graue Bildunterschrift; keine Schilder auf Bildern; nie halbe Wörter in Produktbildern.
- **Angebot:** überall gleich — „Solicitar una demo“ (schwarz) + „Piloto gratuito · precio en la demo“. Die 14-Tage-Prueba verschwindet aus beiden Sichten (Owner O-1 = ja); der Schlüssel `trial` bleibt im Code für später.

## 5. Bibliotheken (Gewicht, Ladezeit, Entscheidung)

| Option | Gewicht (gzip, Herstellerangabe) | Entscheidung |
|---|---|---|
| **Motion** (schon im Repo als `framer-motion`, `LazyMotion` + `domAnimation`) | min. ≈ 3 kB, bei uns ≈ 15–20 kB durch die genutzten Teile; scroll-gebundene Animation (`useScroll`) und In-View ohne Zusatzgewicht, hardwarebeschleunigt (https://motion.dev/docs/gsap-vs-motion) | **bleibt die eine Bibliothek.** Scroll-Erzählung, Stapel-Karten, Zähler, Einblenden: alles mit `useScroll`/`useInView` + CSS `position: sticky`. Kein zweites Animationssystem. |
| GSAP + ScrollTrigger | Kern ≈ 24–27 kB + ScrollTrigger ≈ 17 kB; seit 2025 kostenlos „für alle“ dank Webflow (https://gsap.com/pricing/) | **nein:** ≈ 40 kB mehr für Dinge, die Motion und CSS schon können; zwei Animationsmodelle nebeneinander wären genau das „Flickwerk“, das weg soll. |
| Lenis (Smooth Scroll) | < 5 kB (https://lenis.dev/) | **nein, nicht jetzt:** natives Scrollen bleibt (60 fps auf Mittelklasse-Handys, keine Hijack-Risiken mit `scroll-snap`, Tastatur und Screenreadern). Falls die Zwischenschau 3 ein spürbares „Ruckeln“ zwischen Sticky-Abschnitten zeigt, ist Lenis die eine Ergänzung (OWNER-Entscheidung, Gewicht < 5 kB). |
| CSS Scroll-Driven Animations (`animation-timeline: scroll()`) | 0 kB | **ja, als Zusatz** für den Fortschrittsbalken der Scroll-Erzählung und die Stapel-Karten auf Chrome/Edge/Safari 26; Motion bleibt der Fallback, wo der Browser es nicht kann. |
| Recharts | ≈ 95 kB, nur auf `/example-report` | bleibt dort; auf der Startseite keine Chart-Bibliothek (die Balken sind CSS). |

Ladezeit-Ziel (Punkt 9c): LCP < 2,5 s Handy-4G (Hero-Poster 960 px vorgeladen, Video `preload="none"`, erst nach dem ersten Bild), Lighthouse ≥ 90 Handy / ≥ 95 Desktop, CLS < 0,1 (jede Karte mit fester Höhe oder `aspect-ratio`, keine Layout-Sprünge durch nachladende Bilder).
