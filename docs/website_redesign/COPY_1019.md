## 0. Two of the flagged sentences are mine, and they were wrong

The hero's state line on the rendered `/es` reads:

> *Hoy respondemos en español. El sistema responde en el idioma del cliente; lo que falta en otros idiomas es
> la aprobación legal del aviso…*

That is **my L-1 and L-2** from `TEXTS_1013.md` §4, released by this lane on 2026-10-13 as lines for the
public build. L-2 was written from the production **bytes** — the language rule is in the agent — and the
Gate table is right that this is not what a sales page may claim: in production a reply in another language
**does not exist**. A capability in the code that no customer can receive is not an offer.

My **L-3**, "si alguien escribe en un idioma sin aviso aprobado, no enviamos nada y queda una tarea para tu
equipo", is the other flagged sentence, now on the platform page as "otro idioma queda como tarea para tu
equipo". The task is **staging only** (14/14); in production the turn is held and **nothing** is created.

Both are withdrawn from `TEXTS_1013.md` §4 by this file and replaced in §2 below. The lesson is recorded
for this lane: a line goes to the public build from the **production** column of the evidence, never from
the bytes or from staging.

## 4. C3 — two owner templates. Nothing is published without the owner

### 4.1 The public name of the morning assistant

The internal names (Jarvis, Daily Goals) are not public, and the owner rejected Jarvis on the page. Two
options, each with its effect:

| | Option 1 — a descriptive name | Option 2 — a short proper name |
|---|---|---|
| ES | **El parte de la mañana** | **Alba** |
| EN | **The morning brief** | **Alba** |
| What it does | says exactly what it is; "el parte" is the everyday Spanish word for the daily work report | gives the feature a voice; "alba" is dawn, so the morning sits inside the name |
| Effect on trust | no expectation beyond what exists: a list, a reason, a next step | a personal name **suggests a conversation partner**. The chat that would justify that is **not in production** (Daily row 11). A name that promises more than the product is the problem this whole register exists to prevent |
| Effect on disclosure | none | an AI with a human first name has to say it is an AI everywhere the name appears |
| Risk | generic, not ownable as a brand | a **trademark check is needed**; this lane has not done one and does not claim the name is free |
| **This lane's view** | **now** | **later**, once the conversational assistant is in production and the check is done |

### 4.2 How a price is shown

No amount exists and none is written here: the catalogue reports `awaiting_pricing_authority`. The template
is about **how** the price appears once the owner sets it.

| | Option A — every price published | Option B — every price on request | Option C — Essential published, the rest on proposal |
|---|---|---|---|
| on the page | "Essential desde {importe} €/mes · Growth desde … · Enterprise desde …" | "Te decimos el precio para tu agencia antes de acordar nada." | "Essential: {importe} €/mes. Growth y Enterprise: te enviamos una propuesta." |
| effect | agencies qualify themselves, fewer calls, easy comparison | maximum flexibility per agency | a visible entry price matching the self-service trial, and room above it |
| cost | anchors low; hard to price a five-office agency and a one-person one alike | friction, and it contradicts the "no sales call" promise of the trial path | two price logics on one page, which the page has to explain in one line |
| **This lane's view** | | | **C.** It is the only one consistent with what the site already promises: Essential is tried alone and without a call, Growth and Enterprise are proposals |

**For any option:** the interval is stated with the amount, and the four payment steps stay as they are —
an issued invoice activates nothing, the confirmed payment does, and there is no card payment.
